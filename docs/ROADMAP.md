# From prototype to a useful browser workstation

The first milestone is implemented: a real kernel boot, shell and graphical access to real Linux files, with persistence and recovery. The next milestones are ordered by dependencies rather than cosmetic desktop features.

1. **Kernel reliability and a source build.** Establish a reproducible build in an isolated Linux environment, compare the current upstream kernel/runtime against this pinned prototype, and find the intermittent file corruption. Stress task exit, process creation, simultaneous shell/bridge calls, multiple memory sizes, repeated reloads and long background sessions. Require no silent corruption and dependable failure recovery before calling the workstation reliable.
2. **A supported application ABI.** Document the exact compiler, musl and kernel interfaces. Build a small useful tool set against that ABI, publish verified packages and maintain compatible versions together. Ordinary distro binaries cannot be promised to work. A Wasm/WASI syscall adapter could broaden compatibility but would need real semantics and dedicated tests.
3. **Storage that scales.** Introduce a versioned filesystem or block-device layer backed by browser storage such as OPFS. Preserve Unix metadata, implement crash recovery and migration, and benchmark the result on mobile. Keep portable backup/export as a first-class feature.
4. **Network and graphics devices.** Design explicit browser-backed devices. HTTP/WebSocket access has browser restrictions; arbitrary Linux networking would require a clearly disclosed relay or a different transport. A graphics protocol/compositor and browser GPU path need a real implementation before claiming native Linux GUI applications.
5. **Performance and device support.** Measure representative application workloads against native builds; profile syscalls, scheduling, worker churn and memory. Use capability-based resource budgets and real tests on iPhone Safari, Android, Chromebook and low-memory hardware. Add a second execution path only where measurements justify its complexity.
6. **A distributable product.** Finish source/license packaging, accessibility, update rollback, compatibility diagnostics and a documented browser support policy. Host the static app with the required isolation headers. Installation or service workers should remain optional conveniences, with normal website access as the entry point.

Success means giving users the strongest Linux environment that their browser can actually support. It does not require escaping the browser sandbox or changing their host operating system.
