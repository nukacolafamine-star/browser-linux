# Verification record

## Live GitHub Pages verification

The deployed HTTPS site at https://nukacolafamine-star.github.io/browser-linux/ was tested in a fresh Chrome profile at a 390px touch viewport. The first visit reloaded once, enabled shared memory and booted the real kernel. A guest file was written and saved; an offline page reload booted Linux again and restored the exact contents. No uncaught browser errors were observed. See `verification/live-pages-report.json`.

GitHub Pages returns 404 for `.nojekyll`, so host marker files are excluded from the offline cache. The Pages regression test now reproduces that behavior and passes eight checks. Physical iPhone Safari remains untested.

Tests ran on the existing Windows host with Node 22.20.0 and locally installed Chrome 154.0.8037.57 / Edge 153.0.4234.48. Browser automation used fresh temporary profiles. No native Linux installation was used.

## Failures found and current status

1. A binary file once contained changed bytes after a page reload. The original write readback had passed. The root cause remains unresolved; it could be in the kernel, userspace/runtime or bridge. Later repeated tests have not reproduced it. Graphical writes now read back exact bytes; stored backups have SHA-256 fingerprints; full restores are compared with the source backup before autosave starts. Two snapshots must agree before a save is committed. These are detection/recovery measures, not proof of a kernel fix.
2. Some boots reached the init banner but not the shell prompt. One failed offline-reload boot logged a Wasm out-of-bounds memory fault in init. This is also unresolved. Readiness now requires both the bridge and shell; execution faults are reported immediately and a stalled boot reaches a visible error after 45 seconds. Restart is available without discarding the saved workspace. Tests do not silently retry or count a failed boot as a pass.
3. Offline readiness sometimes remained pending despite an already activated worker/cache. The UI now reads the active registration independently of a potentially pending update request. A subsequent end-to-end run successfully booted while the browser was offline.
4. An 8 MiB hashing test initially hashed zero bytes because `/dev/zero` was absent from the upstream initramfs. Standard device nodes are now included, and the test checks the digest against independently generated bytes.

512 MiB mode, physical mobile devices, Safari/Firefox, storage-quota exhaustion, long background suspension, hostile guest programs and sustained workloads have not been validated. No production reliability claim is made.
